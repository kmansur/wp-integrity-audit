# Security Policy

The Python branch is a development release and has not completed an end-to-end recovery test. Do not use the invasive modes on production systems.

Report vulnerabilities privately through GitHub private vulnerability reporting if enabled, or through an established secure maintainer contact. Do not post credentials, attack payloads, customer data, dumps, or forensic archives in public issues.

Treat the case directory, SQL dumps, archived WordPress trees, and database access metadata as confidential incident evidence. Read-only audits create local reports; recovery creates full site and database backups. Rotate any secret that may have entered Git history, even after removing it from the latest revision.
